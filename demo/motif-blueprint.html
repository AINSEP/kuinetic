Sheet 01  /  Fig. 00  /  Title block

kUInetic

A CSS animation library
authored in HTML attributes

You write one attribute on one element — data-kui="fade-up" — and the library compiles it into a real CSS @keyframes animation and, where the browser has them, a native scroll-driven timeline. No animation loop. No JavaScript to write. The sheets below document the machine: what the attribute is, what it turns into, and where every part of it lives in the source.

Fig. 01  /  Mechanism  /  Exploded view

One attribute in.
Three real CSS artefacts out.

Nothing here is a metaphor for compilation. The attribute is parsed, resolved against a registry, and turned into ordinary CSS the browser runs on its own. Each panel below is quoted from the file named on it.

Ref. IN — authored markup your page

<h2 data-kui="fade-up">
  One attribute.
</h2>

That is the whole authoring surface. Timing is positional and optional — fade-up 900ms 150ms ease-out reads duration, delay, easing, in that order. steps(8,end) is a legal easing token too, which is what gives this sheet its stepped, plotted motion.

Ref. A-1 — parameter defaults src/css/presets.generated.css:412

/* generated from the preset's declared params */
[data-kui-fx~='fade-up'] {
  --kui-reveal-duration: 600ms;
  --kui-reveal-delay: 0ms;
  --kui-reveal-ease: ease-out;
}

Ordinary rules, not !important, so your own CSS can override any default without a fight.

Ref. A-2 — the keyframe block src/css/entrance.css:23

@keyframes kui-in-up {
  from {
    opacity: var(--kui-from-opacity, 0);
    translate: 0 var(--kui-distance, 24px);
  }
}

from-only. The element's own resting style is the to state, so the 48 names of Section A share 29 keyframe blocks.

Ref. A-3 — the declaration written on the element src/core/compile.ts:287

animation-name: kui-in-up;
animation-duration: var(--kui-reveal-duration, 600ms);
animation-delay: calc(
  var(--kui-reveal-delay, 0ms)
  + var(--kui-i, 0) * var(--kui-stagger, 0ms)
);
animation-timing-function: var(--kui-reveal-ease, ease-out);
animation-iteration-count: var(--kui-fx-fade-up-iterations, 1);
animation-fill-mode: both;

Longhands, not the animation shorthand — because composition is expressed as parallel value lists across one declaration. Two effects, two comma-separated entries in every list. See Fig. 04.

Note Every var() above is a knob. --kui-stagger on a parent times a whole group; --kui-distance changes how far the element travels; both are read straight out of the compiled calc(), so overriding one takes a single CSS line and no re-authoring.

Fig. 03  /  Motion profile  /  Plotted traces

Easing is a value you type.

The third positional argument. A keyword, a cubic-bezier(), a steps(), or one of the library's named curves. Each trace below is the real function, plotted progress against time — and each one is drawn on screen by draw-stroke, the library's own SVG primitive.

Ref Named curves are declared once in src/css/base.css:15–30 and reachable from any attribute as a bare word: data-kui="pop-in 500ms 0ms back-out". The draws themselves are linear, on purpose: a plotter head travels at constant speed, and the easing being demonstrated is in the shape of the curve, not in the pen. Traces drawn with data-kui="draw-stroke 1300ms 240ms linear on:enter" on a <path pathLength="100"> — pathLength normalises the path to 100 units, which is the default --kui-path-length, so the draw needs no measurement and the library never calls getTotalLength().

Fig. 04  /  Channel allocation  /  Bus assignment

Two effects share one element
only if they share no property.

Every primitive declares which CSS properties it owns — its channels. Comma-separate two whose channels are disjoint and they compile into one animation. Comma-separate two that both want translate and the library keeps the first and warns in the console naming both. Never a silent drop.

Fig. 05  /  Drive  /  Two independent axes

What starts it, and what drives it,
are different questions.

The most common mistake with this library is treating on: and timeline: as two tiers of the same setting. They are separate axes. One says when the animation is released; the other says what supplies its progress — a clock, or the scrollbar.

Ref. D-1 — activation a clock drives it

<figure data-kui="fade-up on:enter">

Held at its from state — animation-play-state: paused — until an IntersectionObserver releases it. Plays once at its authored duration and stays finished. Scroll back up and nothing rewinds.

Ref. D-2 — timeline scroll drives it

<figure data-kui="scroll-desaturate timeline:view">

/* compiled — src/core/style-plan.ts:110 */
animation-timeline: view();
animation-range: entry 0% cover 60%;

Progress maps continuously to scroll position, so it reverses on the way back up. A duration is close to meaningless here — the scrollbar is the clock. Where the browser has no native timeline the runtime falls back to an on:enter reveal, a documented behavioural difference rather than an equivalent.

Specimen · scroll-desaturate · timeline:view

Scroll this plate up and down. Colour drains and refills with the scrollbar, not with a timer — that is the whole difference between the two panels above.

Fig. 07  /  Installation  /  Bill of materials

Two files. No bundler.

Ref. E-1 — drop-in docs/getting-started.md

<link rel="stylesheet" href="./kuinetic.css">
<script src="./kuinetic.js"></script>
<script>
  kuinetic.kuinetic({ observe: true }).start()
</script>

observe: true keeps a MutationObserver running so elements added later — by your app, a CMS, a client-side router — get picked up automatically. Drop it for a fully static page and the smallest possible init.
